# 实验协议 V3（KPI：易交接 > 可靠性 > 省钱 > 省时）

> 适用范围：`ai-ink-brain-api-python` 初次理解及后续对照实验扩展  
> 与 V1/V2 的关系：V3 **不改变**既有结果文件；产出写入 **独立新文件名**（见下文）。

---

## 1. KPI 优先级与权重（用于汇总打分）

| 优先级 | KPI | 含义（可操作定义） | 建议权重 |
|--------|-----|-------------------|----------|
| P1 | **易交接** | 另一名 Agent/新人 **仅凭本文档冷启动**，能在最少追问下定位入口、契约与改动位置 | **40%** |
| P2 | **可靠性** | 事实可复核（锚点、引用）、少幻觉；不确定项显式列出而非编造 | **35%** |
| P3 | **省钱** | 输入/输出 token 可控（同等信息量下更少冗余） | **15%** |
| P4 | **省时** | 墙钟时间更短（次要；不因抢时间牺牲 P1/P2） | **10%** |

汇总分时：**先评 P1/P2（及格线），再比较 P3/P4**。若 P2 存在未标注的重要幻觉风险，整体结论降级。

## 4. V3 强制章节（两处 Prompt 共用结构，便于对照）

以下为 **P1 易交接** 与 **P2 可靠性** 的落盘载体；两组都必须按相同标题顺序输出（详见各 Prompt）。

### 4.1 易交接（P1）

- **冷启动接手清单**：10～15 步，顺序执行；每步一句可执行动作（如「打开某文件」「运行某 grep」），避免只有概念。
- **锚点索引表**：HTTP 路径、Supabase RPC、主要表名、关键 env → **证据**（`路径` + `函数或行区间` + 一句作用）。
- **新人 FAQ**：6～10 条；每条：问题 → 简短答 → **证据锚点**。
- **改动配方卡**：固定 3 类（新增端点 / 调整检索 / 调整 ingest）；每类：**会动哪些文件**、**必须同步的真值文件**（如 manifest/contract，以代码库实际存在为准）、**验收入口**。

### 4.2 可靠性（P2）

- **事实断言清单**：表格列：`断言 | 证据（路径#L 或函数名） | 核验方式（打开文件/grep/sql） | 置信度（高/中/低）`。
- **不确定性与验证步骤**：凡证据不足的一律列出；禁止用猜测填满缺口。
- **漂移防线（若适用）**：若阅读过程中发现仓库内有 manifest/contract/drift 工具，仅描述 **你从文件中看到的** 用途与路径；未见则写「未核验」。

### 4.3 省钱 / 省时（P3/P4）

- **消耗明细**：统一估算口径（见 Prompt）：便于横向对比。
- **覆盖率**：读过哪些文件、抽样读到哪一行（避免假装通读）。

## 5. 对比文档撰写指引（填写 `compare_core_A_vs_B_v3.md`）

实验完成后，依据两份 `result_*_v3.md` 填写模板，重点顺序：

1. **P1**：哪边的「冷启动清单 + 锚点索引表」更可执行？另一名 Agent 更少往返？
2. **P2**：统计「低置信断言比例」「无证据断言数量」（越低越好）；是否列出契约/manifest？
3. **P3**：在信息量可比前提下对比 `total_tokens`。
4. **P4**：对比墙钟时间（若自报不可靠，以外部计时为准）。
