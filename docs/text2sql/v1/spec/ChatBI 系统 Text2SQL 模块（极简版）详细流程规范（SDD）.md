# 1\. 概述

本规范定义 ChatBI 系统 Text2SQL 模块的核心执行流程，聚焦“自然语言→SQL→数据→自然语言”的极简链路，暂不包含权限校验、审计日志等企业级增强功能，用于快速落地 Text2SQL 基础能力，后续可通过接入 Vanna 进行功能升级。

# 2\. 核心范围

仅实现 Text2SQL 基础功能，覆盖“意图识别→表结构检索→SQL生成→执行→结果总结”全链路，暂不涉及：权限控制、敏感字段过滤、异常重试、审计日志等模块。

# 3\. 整体执行流程（核心 Spec）

## 3\.1 输入输出定义

- 输入：用户自然语言查询（仅限需要查询结构化数据库的问题）

- 输出：自然语言回答（包含查询结果）

## 3\.2 详细执行步骤

### 步骤1：用户输入

用户提交自然语言查询（例：“查询3月份各部门支出金额”），系统接收并存储查询文本。

### 步骤2：意图识别（极简版）

通过简单语义判断，确认用户查询为“结构化数据查询”，直接进入 Text2SQL 专用流程（暂不做通用知识问答分支，简化判断逻辑）。

### 步骤3：Text2SQL 专用 RAG 检索

基于用户查询文本，通过 FAISS 向量库检索以下核心信息，用于辅助 SQL 生成：

- 相关数据库表结构（DDL，含表名、字段名、字段类型、简单注释）

- 相似历史问题与示例 SQL（极简版可手动录入3\-5条作为初始样本）

### 步骤4：LLM 生成 SQL

将用户查询、检索到的表结构、示例 SQL 拼接为 Prompt，调用 LLM 生成标准可执行 SQL，要求：

- SQL 语法正确，可直接在目标数据库（MySQL/PostgreSQL）执行

- 仅包含检索到的表和字段，不生成不存在的表/字段

- 贴合用户查询意图，不偏离核心需求

### 步骤5：SQL 基础校验

执行前进行极简校验，避免基础错误：

- 仅允许 SELECT 语句，禁止 UPDATE、DELETE、ALTER、DROP 等写操作

- 校验 SQL 语法合法性（简易校验，可调用数据库语法校验接口）

### 步骤6：数据库查询执行

连接目标业务数据库，执行生成的 SQL，获取结构化查询结果，处理基础异常（如 SQL 执行失败、连接超时），返回查询结果集。

### 步骤7：自然语言总结

将数据库返回的结构化结果（表格/数据集），通过 LLM 转换为简洁、易读的自然语言，贴合用户查询意图进行总结（例：“3月份各部门支出金额如下：IT部门5000元，市场部门8000元\.\.\.”）。

### 步骤8：结果返回

将自然语言总结结果返回给用户，完成一次 Text2SQL 查询流程。
